# 测试规范

本页为**语言无关**的测试专项规范，与 [编码规范](coding-standards.md) 中的「测试规范」章节互补。
适用于所有使用 `cargo test`、`pytest`、`jest` 等测试框架的项目。

## 测试注释

每个测试用例前必须写文档注释，用中文说明**测试目的与验证要点**，
而非复述测试名。注释回答的问题是"该测试验证了什么"，不是"测试名叫什么"。

### 边界与集合测试策略

- **若测试对象存在边界条件**：必须测试边界值（如长度限制 64/65、256/257、金额正负号等），
  以及边界两侧的行为。
- **若测试对象不存在明确边界**：应测试一个**集合**。
  若集合中的元素存在与测试无关的内容（如时间字符串中的时/分/秒对月份解析无影响），
  则尽可能**随机化**这些无关内容，以覆盖更大的取值空间、避免偶然通过。

### 相等断言必须配套不相等断言

只测「相等」的实现很容易通过假阳性（例如把输入原样返回、或错误地约掉有效数位）。
因此每个判断相等的断言之外，必须再给出**至少一个判断不相等**的用例：

```rust
// 相等：约分正确
assert_eq!(Money { value: -410, divisor: 100 }.normalized(), Money { value: -41, divisor: 10 });
// 不相等：数值不同的金额不能被误判为相等（防止实现「约多了」/丢掉小数）
assert_ne!(Money { value: -410, divisor: 100 }.normalized(), Money::from_int(-4));
```

### 数值类测试必须覆盖负数域

金额、差值、余额、坐标等可能取负的数值，不能只测正数：
必须补齐负数与零的用例（如 `-0.05`、`-1.23`、`-4.1`），
否则符号处理错误（如「先减小数再取负」）无法被发现。

### 随机化取值（不引入额外依赖）

无明确边界的取值空间用随机测试覆盖，但**不要为此引入 `rand` 等新依赖**：
用固定种子的线性同余生成器（LCG）写几行辅助代码即可，既随机又可复现。

### 禁止使用固定字面量测试长度类约束

**中文字符在 SQLite 的 `length()` 中按字节计数**，而 Rust 的 `chars().count()`
按 Unicode 标量计数，两者结果不同。测试长度限制时：

- 使用 ASCII 字符（如 `"a".repeat(n)`）测试长度的边界，避免依赖语言间字符计数差异；
- 不要想当然地认为"一个中文字符长度就是 1"。

```rust
// 错误：中文字符计数可能掩盖边界错误
let long = "长".repeat(257);

// 正确：ASCII 字符明确表示"字符个数"
let long = "a".repeat(257);
```

## 测试数据

- 禁止在项目目录产生临时文件垃圾：数据库等有状态测试优先使用内存库
  （如 SQLite `open_in_memory`）。
- 必须使用临时文件时，使用唯一路径（如进程 ID + 递增计数器），并立即清理。
- 测试数据应覆盖 happy path、边界条件、错误路径三类（见 coding-standards.md）。

## 平台差异测试

Web（wasm）与桌面（native）平台存在差异（如 HTTP 客户端、定时器实现），
需通过 `#[cfg(target_arch = "wasm32")]` 条件编译封装差异函数；
平台无关的测试应优先在 native 目标下运行（`cargo test` 默认目标）。
